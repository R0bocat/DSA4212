# How much does general text help a small language model learn a narrow domain?

Small decoder-only language models (13.9M parameters) trained **from scratch** on PubMed abstracts mixed with FineWeb-Edu,
under a fixed budget of **45 minutes on one AMD RX 6900 XT** (300M training tokens, fp16). We vary the domain share δ, the
amount of unique domain data U, regularisation, the training horizon, and how PubMed-like the general data is.
Report: `report/` (source + figures + bibliography). Authors: `authors.md`.

## Repository layout (every script resolves its paths relative to the repository root, so commands work from any directory)

| path | contents |
|---|---|
| `code/` | all experiment, data-preparation, analysis and plotting code (no edits needed to run from the root) |
| `runs/` | one folder per training run: `summary.json`, `log.jsonl`, `stdout.txt` (checkpoints `best.pt` are **not** committed, ~55 MB each) |
| `results/` | aggregated numbers: `results.csv` (one row per run), `pools_summary.json`, `run_plan.txt`, `data_stats/` |
| `report/` | `report.tex` (or `.md`), `references.bib`, `figures/` (generated by `code/analyze*.py`) |
| `tokenizers/` | `mix8192.json`, the shared byte-level BPE tokenizer used by every run |
| `ROCm/` | GPU / PyTorch setup notes and the outputs that verify it |
| `data/` | **empty in the repo** (too large); filled by the data-preparation steps below |

## Environment
- Hardware: AMD Radeon RX 6900 XT (gfx1030, 16 GB). OS: Windows 11.
- Python 3.12.16; PyTorch `2.10.0+rocm7.12.0a20260204` (AMD nightly ROCm build for gfx103X), HIP 7.2.0. Setup and pinned versions: `ROCm/README.md`.
  Nightly wheels can disappear from the index; if so, any PyTorch build that sees the GPU works, but timings and last digits will differ.
- Other dependencies: `pip install -r requirements.txt` (numpy, tokenizers, pyarrow, datasets, huggingface_hub, matplotlib).
- fp16 is used everywhere (bf16 is 7-11x slower on this GPU, see `ROCm/`).

## Reproducing the results
Aggregate numbers in the report come from `results/results.csv`; every row is one `runs/<name>/summary.json`.

**Level 0 - regenerate all tables and figures (seconds, CPU only, no data):**
```
python code/analyze.py results/results.csv --out report/figures
python code/analyze_similarity.py runs --pools results/pools_summary.json --out report/figures
```
**Level 1 - re-run one cell (about 45 min on the GPU, needs the prepared data).** Expect test PubMed bits/byte 1.09 +- 0.01 (three seeds gave 1.0875, 1.0929, 1.0965):
```
python code/train.py --domain-dir data/pubmed_v2 --general-dir data/fineweb_v1 --domain-frac 0.3 --domain-unique-tokens 10000000 --tokens 300000000 --lr 1e-3 --eval-interval 2000 --time-limit-min 45 --name check_U10M_d0.3
```
**Level 2 - the full experiment grid.** `python code/run_queue.py --lr 1e-3 --dry-run` prints every run with its settings (saved in `results/run_plan.txt`); runs are resumable.
```
python code/run_queue.py --lr 1e-3 --max-priority 16     # core grid, baselines, dropout controls, seeds, horizon, U=1M/20M
python code/run_queue.py --summarize                     # -> runs/results.csv  (copy to results/results.csv)
```
**Similarity extension** (needs the checkpoints of `runs/S_Uall_d1.0_s1337` and `runs/S_Uall_d0.0_s1337`, which Level 2 regenerates, plus FineWeb shard 1 prepared like shard 0 into `data/fineweb_v2`):
```
python code/score_similarity.py --train-bins data/fineweb_v1/train.bin data/fineweb_v2/train.bin --pm-run runs/S_Uall_d1.0_s1337 --gen-run runs/S_Uall_d0.0_s1337 --ref-bins pubmed=data/pubmed_v2/val.bin fineweb=data/fineweb_v1/val.bin --tokenizer tokenizers/mix8192.json --out data/similarity/scores.npz
python code/build_pools.py --scores data/similarity/scores.npz --eval-bins data/pubmed_v2/val.bin data/pubmed_v2/test.bin --general-dir data/fineweb_v1 --out data/fw_pools --k 4 --tokenizer tokenizers/mix8192.json
python code/run_queue.py --lr 1e-3 --max-priority 19
```
Pause the queue while scoring: sharing the GPU slows training runs and can trip their 45-minute limit.

## Reproducibility notes
- Exact bit-for-bit reproduction is not expected (GPU non-determinism, nightly PyTorch). Seed noise: pooled SD about 0.003 bits/byte (12 degrees of freedom); differences below about 0.009 between two single runs are not significant.
- All evaluation numbers are test bits/byte at the best-validation checkpoint (`best_test_domain_bpb`); `final_test_*` is the last weights.
- Not included: raw/prepared data and checkpoints (regenerated by the steps above).
